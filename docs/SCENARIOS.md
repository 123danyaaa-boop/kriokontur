# Сценарии и протокол тестирования

Документ отвечает на два вопроса жюри: какие сценарии посчитаны и как именно они посчитаны,
чтобы результат можно было повторить. Каждый сценарий это отдельный файл в `configs/scenarios`
со статусом, правилом сочетания шоков и списком изменённых параметров.

Воспроизведение: `PYTHONPATH=src python scripts/run_all_scenarios.py --plan configs/plans/final-candidate.json`

---

## 1. Каталог сценариев

| Сценарий | Статус | Что меняет | Зачем |
|---|---|---|---|
| `BASE` | CASE_INPUT | ничего, контрольные условия | базовый план и проверка ограничений |
| `MANDATORY_STRESS` | CASE_INPUT | спрос +15% с 2038, цена Earth-Core и Earth-Flex +25% в 2038–2039, фактическая поставка Луны 55% и 75%, потолок потерь 2% | обязательный стресс кейса |
| `LOW_DEMAND` | TEAM_SENSITIVITY | колонка `low_total_t` | нижняя контрольная точка спроса |
| `HIGH_DEMAND` | TEAM_SENSITIVITY | колонка `high_total_t` | верхняя контрольная точка спроса |
| `TEAM_COMBINED_STRESS_HIGH` | TEAM_RESEARCH | обязательный стресс на высоком спросе | объявленная комбинация, которую кейс запрещает получать автоматически |
| `TEAM_RISK_EARTH_NEW_DELAY` | TEAM_RESEARCH | подготовка Earth-New 24 месяца вместо 18 | риск верхней границы интервала кейса |
| `TEAM_RISK_ISRU_UNDERPERFORMANCE` | TEAM_RESEARCH | поставка Луны 50 / 60 / 70% плана | риск тяжелее профиля надёжности кейса |
| `TEAM_RISK_CORE_OUTAGE` | TEAM_RESEARCH | доступная мощность Earth-Core 50% в 2037 | срыв у поставщика при сохранении take-or-pay |
| `TEAM_GEO_PRICE_SHOCK` | TEAM_RESEARCH | цена земных каналов 1,25–1,6 в 2036–2038 | геополитический блок на базе BASE |
| `TEAM_GEO_WITH_STRESS` | TEAM_RESEARCH | тот же ценовой шок поверх обязательного стресса | демонстрация правила сочетания без двойного счёта |

Дополнительно геополитическое событие можно собрать на лету: каналы, период, множитель и
компонента цены задаются пользователем через `POST /api/geo` или функцию `risks.geo_event`.

---

## 2. Правила сочетания шоков

1. Контрольные сценарии не меняются никогда. Любое наше изменение живёт в отдельном файле
   со статусом `TEAM_*` и наследуется через `base_scenario`.
2. Один и тот же эффект не начисляется дважды. В комбинированном тесте спрос берётся из
   высокого варианта кейса, а множитель 1,15 обязательного стресса к нему не применяется.
   В геополитическом сценарии поверх стресса цена меняется только в тех годах, где стресс
   её не трогал (2036, 2037 и 2040).
3. Вероятностный блок и сценарные доли поставки независимы: в Монте-Карло случайный отказ
   умножается на сценарную долю, а не заменяет её и не удваивает эффект.
4. Возврат к контрольным условиям делается выбором сценария, параметры события нигде не
   сохраняются в `CASE_INPUT`.

## 3. Протокол теста

Для каждого эксперимента фиксируется:

| Поле | Где хранится |
|---|---|
| идентификатор сценария и плана | `RunResult.scenario_id`, `plan_id`, таблица `run` |
| версия набора данных (sha256) | `RunResult.case_version` |
| версия движка | `RunResult.engine_version` |
| допущения команды | `plan.assumptions`, таблица `plan_assumption`, секция `assumptions` в выгрузке |
| seed для случайных расчётов | параметр `seed` Монте-Карло, печатается в отчёте |
| метрики | приведённые расходы, обслуживание общее и критическое, дефицит, потери |
| критерий нарушения | список `violations` с кодом, годом, фактом, лимитом и превышением |

Повторный запуск на тех же входах даёт те же числа: Монте-Карло детерминирован по seed,
остальные расчёты детерминированы полностью. Это проверяется тестами
`test_monte_carlo_is_deterministic_with_seed` и `test_threshold_finds_boundary_and_is_reproducible`.

## 4. Анализ чувствительности

Инструмент: `scripts/sensitivity_report.py`, модуль `sensitivity.py`, восемь параметров с
обоснованными диапазонами (`GET /api/params`).

| Параметр | Диапазон | Обоснование диапазона |
|---|---|---|
| спрос, множитель | 0,8–1,4 | покрывает низкий и высокий варианты кейса с запасом |
| цена Earth-Core и Earth-Flex | 0,8–1,8 | обязательный стресс даёт +25%, проверяем шире |
| фактическая поставка Луны | 0,3–1,0 | стресс задаёт 55% и 75%, надёжность кейса 0,78–0,93 |
| доступная мощность Earth-Core | 0,4–1,0 | сбой у поставщика без снятия take-or-pay |
| ставка дисконтирования | 0–15% | ставка не задана организатором |
| подготовка Earth-New | 18–24 мес. | интервал самого кейса |
| начальный запас | 0–40 т | решение команды о подготовительном периоде |

Три разных вопроса разделены: развёртка показывает форму зависимости, порог показывает
границу выполнимости, торнадо ранжирует параметры по влиянию на приведённые расходы.

## 5. Обратный стресс

Поиск ближайшего значения параметра, при котором появляется жёсткое нарушение. Метод:
деление отрезка пополам при допущении монотонности метрики по параметру внутри диапазона.
Допущение раскрывается, а результат сопровождается значениями на обоих концах отрезка,
поэтому его легко перепроверить вручную.

---

## 6. Вероятностный блок

Монте-Карло применяется только там, где у нас есть основание для распределения, и с явной
трактовкой:

- `reliability` из `data/supply_sources.csv` трактуется как вероятность полной годовой
  поставки канала;
- при отказе фактическая доля берётся из `Uniform(0,5; 0,9)` (TEAM_ASSUMPTION);
- отказы независимы между каналами и годами (TEAM_ASSUMPTION, зависимости не заявлены);
- число испытаний и seed печатаются вместе с результатом;
- результат читается как вероятность нарушения при этих допущениях, а не как вероятность
  реального события.

Отчёт: `scripts/risk_report.py`, эндпоинт `POST /api/montecarlo`.

---

## 7. Реестр рисков

`configs/risks.yaml` связывает каждый риск со сценарием, который реально пересчитывается.
Последствие считается как разница прогонов «сценарий риска» и базового сценария на одном плане:
`ΔPV`, `Δдефицит`, `ΔSL` и список нарушений. Где статистики нет, вероятность не выдумывается,
а указывается диапазон или прочерк с объяснением.

Мера и остаточный риск проверяются тем же способом: план с мерой прогоняется по тому же
сценарию, разница между «до» и «после» это эффект меры, а оставшееся отклонение это остаточный риск.

---

## 8. Расширяемость

`scripts/extensibility_demo.py` на копии набора данных:

1. добавляет шестой канал Source-X одной строкой в `supply_sources.csv`;
2. добавляет 2041 год одной строкой в `demand.csv`;
3. показывает, что обязательный расчёт продолжает считаться на исходном наборе.

Расчётная логика при этом не меняется: движок перебирает каналы и годы из данных,
а доступность канала выводится из `available_from_year` плюс правила инвестиционного ввода.
